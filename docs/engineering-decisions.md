# Engineering Decisions

## 1. Keep the core score deterministic

ClearScan's core scoring engine is deterministic and rule-based rather than LLM-based. It uses TF-IDF keyword extraction, a custom skills taxonomy, and U.S. Department of Labor O*NET occupational benchmarking data.

This makes the scoring path deterministic. It also means ClearScan should not be described broadly as an AI-powered scoring product. Determinism and speed matter on this path: the same résumé should score the same way, and the measured end-to-end parse is under 6 seconds. An LLM in that loop would add non-repeatable output to the thing every free user depends on.

### Why O*NET specifically

O*NET is official U.S. Department of Labor occupational data. Using it gives the skills taxonomy an external, public benchmark instead of an invented internal list of "what a role should look like." Recruiters and job seekers can recognize that source. It is a legitimacy choice, not a claim that the score is an official government assessment.

## 2. Restrict Claude to two premium features

The Anthropic Claude API is used only for:

- AI-assisted bullet rewrite suggestions
- AI-generated cover letters

These features are gated behind the paid subscription. The product applies generative AI where generated language is the requested output instead of making it a dependency of the core score.

### Why these two features, specifically

Bullet rewrites and cover letters are generative writing tasks. The user is asking for new prose. LLM output is the deliverable. Scoring is the opposite problem: it should be fast, repeatable, and stable. Mixing those jobs would put an LLM in charge of a number that needs to be stable.

For bullets, the user selects a bullet point, requests an AI rewrite, and receives a suggested improved version grounded in the scan results. It is designed not to invent facts. For cover letters, the user provides résumé text and job description text only. Neither feature replaces the score.

## 3. Separate free scoring value from paid generation

Every free user receives the deterministic score, verdict, top issues, a keyword preview, a section check and rule-based suggestions. Full keyword lists, skill analysis, the five-platform ATS details, bullet analysis and interview probability are paid, as are the two Claude-backed generation features.

This split allows:

- Full core scoring without an LLM call
- Clear product communication about which results are deterministic and which are generated by AI

## 4. Treat user-found defects as product defects

Issues reported from real résumés are treated as product defects, fixed, and covered by automated tests.
